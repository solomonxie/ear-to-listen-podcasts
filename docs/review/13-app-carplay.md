**Checklist results:**
- UIScene lifecycle: clean. The app is a SwiftUI `App` with a `WindowGroup`, so it already uses scenes, and the iOS 27 "no scene lifecycle" trap doesn't apply. The manifest declares only `CPTemplateApplicationSceneSessionRoleApplication`. With no `UIApplicationDelegateAdaptor`, SwiftUI's own delegate serves the window role, which is Apple's documented pattern for CarPlay with SwiftUI. `UIApplicationSupportsMultipleScenes = true` is required for the CarPlay scene. `TARGETED_DEVICE_FAMILY = 1`, so it doesn't open iPad multi-window, including in App Review's iPad compatibility mode. `CarPlaySceneDelegate` is a `UIResponder` with `CPTemplateApplicationSceneDelegate`, and the class name in the manifest matches.
- Launch path: `App.init` only registers providers and adds one observer. The first frame waits on the DB open and every migration on main (P2 #2). The `try!` there is 01 #1.
- Background tasks: none. No `BGTaskScheduler` use and no `BGTaskSchedulerPermittedIdentifiers`, which is consistent. `UIBackgroundModes` is `audio` only, and auto-sync is foreground-only by design.
- CarPlay: the list-length cap is respected everywhere (`limit`, `CarLibrary.window`, and `limit / 2` + rest in Listen Now). DB reads are off-main, one query per list, and images are ImageIO thumbnails made off-main into an `NSCache`. `libraryDidChange` is debounced (400 ms). But the observer traps when the notification comes from a sync (P0 #1). Now Playing is pushed again when it's already on the stack, and depth has no bound (P0 #2). Play/pause rebuilds everything from a full-library read (P2 #1).
- Private API: none. `SwipeToGoBack` is a public `UIPanGestureRecognizer` subclass that sets `state`, attached to the key window. That's allowed and is the same technique `KeyboardDismissal` uses. The gesture stands down while anything is presented, and while a page is pushed in the player.
- `GeneratedCover`: a `GeometryReader`, gradient, `Canvas` (at most about 40 shapes) and up to three `Text`s with a shadow. It isn't cached as a bitmap, and doesn't need to be at this cost. But `ArtworkTile` draws it under every loaded picture as well (P3).
- Dead code: `sectionTitle()`, and `UnfoldingPicker.valueAlignment` (no caller sets it, so the `.leading` branches never run). The CarPlay target code ships in Release without the entitlement (P3). Every other helper has at least one caller.

Summary: the shell is in good shape. Scene setup is correct for iOS 27, there's no private API, and the CarPlay data layer follows the repo rules (one query per list, off-main thumbnails, debounced refresh). The two serious problems are both in `CarPlayController`'s plumbing. Its notification sink asserts it's on the main actor, but syncs post `libraryDidChange` from the cooperative pool, so importing anything while the car is connected crashes the app. Its Now Playing push doesn't check whether Now Playing is already on the stack, so the album/artist and Up Next loops push it again with no depth limit. The rest is launch-time migration on main, a car refresh on every play/pause that re-reads the whole library, list artwork decoded on main without a cache, and a scroll handle that jumps the list back to a stale spot. **P0 2 · P1 0 · P2 4 · P3 12**

## P0

**1. The CarPlay observer traps when a sync posts `libraryDidChange`, which happens off the main thread.**
`CarPlayController.swift:52-58`; `Sync.swift:182`, `:224`, `:298`, `:310`, `:347`; `SyncQueueManager.swift:282`
- The merged publisher's `sink` runs `MainActor.assumeIsolated { self?.refreshSoon() }`. `NotificationCenter.publisher` delivers on the posting thread. `SyncEngine` is a non-isolated struct, and its `sync`/`perform` are non-isolated `async`. Under Swift 6 with no `NonisolatedNonsendingByDefault` in `project.yml`, they run on the global executor, even when called from the main-actor `SyncQueueManager.drain`. The comment at `Sync.swift:208` says so on purpose. Every import, relink, tag read and listing then posts `libraryDidChange` from a background thread. `assumeIsolated` off main is a `fatalError` in Release too.
- `SourceRefresh`, `EpisodeRemoval` and `ArtworkSidecar.adopt` post from non-isolated async code too (PLAUSIBLE for each, depending on caller).
- Scenario: driving with CarPlay connected and the phone unlocked in a mount. The 15-minute scheduled sync finds one new episode, and the app crashes, taking playback with it. It crashes again on every sync until the car is unplugged. Today only `CARPLAY=1` builds carry the entitlement, so TestFlight with CarPlay is affected and the App Store build isn't yet.
- Fix: `.receive(on: DispatchQueue.main)` before the `sink`, or `sink { _ in Task { @MainActor [weak self] in self?.refreshSoon() } }`. Better at the source: post `libraryDidChange` through one `@MainActor` helper (which also fixes the SwiftUI `onReceive` observers that get it off-main today). The engine publishers are already main-actor-safe.

**2. PLAUSIBLE: Now Playing is pushed again when it's already on the stack, and the album/artist and Up Next loops grow the stack without limit.**
`CarPlayController.swift:301-304`, `:226-230`, `:327-336`, `:357-362`
- `showNowPlaying` only checks `topTemplate !== CPNowPlayingTemplate.shared`. From Now Playing, the album/artist button pushes the speaker's episodes, and Up Next pushes a list. Picking an episode on either page then pushes the shared Now Playing template a second time, while it is still lower in the stack. Repeating that adds two templates per round.
- CarPlay doesn't allow the same template instance in the stack twice, and audio apps have a maximum template depth (5 in the CarPlay guide). Either is likely to raise an exception (a crash). At best the system refuses the push and the tap does nothing.
- Scenario: Listen Now → episode → Now Playing → album/artist → pick another episode. On the second round at the latest, the push either crashes the app or does nothing, while driving.
- Fix: if `interface.templates.contains(CPNowPlayingTemplate.shared)`, `pop(to: .shared)`, otherwise push. For the album/artist and Up Next buttons, pop to Now Playing before pushing, so the stack is never deeper than tab → list → list → Now Playing → one list.

## P2

**1. Every play/pause and track change re-reads the whole library and rebuilds every car list, with a separate image update per row.**
`CarPlayController.swift:56-57`, `:76-83`, `:252-259`, `:274-278`; `CarLibrary.swift:40-66`
- `$isPlaying` and `$currentTrack` feed `refreshSoon`. `refresh()` calls `snapshot()`: `tracks.all()` (the whole table), albums, artists, `SpeakerOrder` over all tracks, 100 bookmarks, a cache directory listing, and the provider list. It then calls every registered build, including the DB query behind each pushed episode list.
- Each build makes new `CPListItem`s with no image, then starts one `Task` per row that calls `setImage` after an actor hop. So the car first draws imageless rows, and then each picture arrives as its own update to the head unit, even on an `NSCache` hit.
- Scenario: 3,000 episodes. Each pause/resume tap on the steering wheel costs a full-table read and about 30 to 60 list-item updates, and the visible list flickers its artwork every time.
- Fix: on `isPlaying`/`currentTrack`, update `isPlaying`/`playbackProgress` on the existing items. They are mutable, so keep a `[trackID: [CPListItem]]` map. Take a snapshot only on `libraryDidChange`/`bookmarksDidChange`. In `CarArtwork`, add a synchronous `cached(...)` lookup and set the image before `updateSections`, falling back to the async path only on a miss. Show `isPlaying` only while the engine is actually playing.

**2. The DB open and every pending migration run on the main thread before the first frame, and again on a CarPlay-only launch.**
`EarToListenApp.swift:5`; `PlaybackEngine.swift:29-32`; `DatabaseManager.swift:16-22`; `CarLibrary.swift:34-38`
- `@StateObject private var playback = PlaybackEngine.shared` is evaluated with the App's first `body`. The engine's stored `ProviderStore(dbQueue: DatabaseManager.shared.dbQueue)` opens the DB and runs `Migrations.migrator().migrate` synchronously on main. A cold launch from CarPlay does the same through `CarLibrary`'s stored stores in `didConnect`.
- Scenario: an update ships a migration that rewrites the library (the v31/v32 folds in 01 were whole-table). On 5,000 episodes it runs for more than the launch watchdog allows. iOS kills the app (`0x8badf00d`) before the first frame, and because the migration transaction rolls back, every launch repeats it. The user just sees a crash. From CarPlay, the car shows "app not responding".
- Fix: make the stores lazy, and open and migrate the DB in a detached task behind a small root gate ("Updating your library…") that the window shows at once. `CarPlaySceneDelegate` awaits the same gate before `start()`. This is also where 01 #1's error screen belongs.

**3. List artwork is decoded on the main thread at draw time, at full stored size, with no cache.**
`ArtworkTile.swift:96-107`, `:78`
- The comment says "Read and decoded off the main thread". But `UIImage(data:)` only parses the header, and the JPEG is decoded lazily the first time Core Animation draws it, which is on main. Stored artwork is up to 800 px, and `ImageFileStore.save(_:)` without `maxDimension` doesn't downscale. A 44 pt row therefore decodes a 2.5 MB bitmap. There's no cache, so in `LazyVStack`/`List`, every row that scrolls back in is read and decoded again.
- Scenario: Home's episode list, flicked quickly through 200 rows with artwork. Each new row costs a file read plus a main-thread decode of several milliseconds, and scrolling drops frames. Memory peaks with every visible 800 px bitmap held at full size.
- Fix: in the detached task, decode at display size with `UIImage(data:)?.preparingThumbnail(of: pixelSize)`, or ImageIO's `kCGImageSourceThumbnailMaxPixelSize` as `CarArtwork` already does. Keep the results in an `NSCache` keyed by `fileName|pixelSize`, and check it synchronously before starting the task.

**4. The scroll handle ignores manual scrolling, so touching it jumps the list back to wherever the handle was last left.**
`ScrollHandle.swift:33`, `:59-72`, `:123-133`
- `fraction` only changes inside the drag. After the listener scrolls by hand, the knob still shows the old position (0 on first show). The drag is `DragGesture(minimumDistance: 0)`, so `onChanged` fires on touch-down with zero translation and calls `scroll()`, which `scrollTo`s `ids[index]` for the stale fraction.
- Scenario: flick a 2,500-file folder down to around file 1,800. The handle appears at the top of its track. Putting a thumb on it to fine-tune sends the list back to file 1. If the listener used it earlier, it goes back to wherever it was last dropped.
- Fix: when not dragging, derive `fraction` from `onScrollGeometryChange` (`contentOffset.y / (contentSize.height - containerSize.height)`) and pass it in as a binding. Or call `scroll()` only once `abs(translation) > 0`.

## P3

- The App and `ContentView` both observe the whole `PlaybackEngine` (`@StateObject playback`, `@ObservedObject engine`) for `isPresentingPlayer` and the environment object. So the scene body and the root `ZStack` (dock bar, Home stack, `MarkFlash`) are re-evaluated on every `currentTime` tick for as long as anything plays. Hold the engine as a plain `let` for `.environmentObject`, and observe `isPresentingPlayer` through a small derived `ObservableObject` or `onReceive(engine.$isPresentingPlayer.removeDuplicates())`. `EarToListenApp.swift:5`; `ContentView.swift:4`, `:27-44`
- The car replays a stale error on connect. `engine.$lastError.compactMap { $0 }` emits the current value on subscribe, and `lastError` is only cleared by the next successful start. A playback failure on the phone an hour ago pops a car alert the moment CarPlay connects. `showError` also replaces any message with "isn't downloaded" whenever the phone is offline, even for "No storage provider configured". The engine's strings are untranslated English. Use `.dropFirst()`, and map typed errors to localized text. `CarPlayController.swift:61-63`, `:340-348`; `PlaybackEngine.swift:188-205`
- Playlists, Collections, Speakers and Bookmarks are cut at `maximumItemCount` with no hint, so collections past the cap (in store order) can't be reached from the car. Episode lists say "Showing x–y of z", and these should too. Listen Later's queue is only the slice on screen, so playback stops after the last shown item. Pass the full `snapshot.listenLater`. `CarPlayController.swift:107`, `:115`, `:153`, `:177`, `:194`, `:214`
- The album/artist button is always enabled but does nothing for an episode with no speaker, or a speaker missing from the last snapshot. Toggle `isAlbumArtistButtonEnabled` on track change. `CarPlayController.swift:296`, `:357-362`
- PLAUSIBLE: `refresh()` isn't cancellation-aware, since `snapshot()` is a detached task and nothing checks `Task.isCancelled` after it. Two overlapping refreshes can then each assign `snapshot` and update templates, and a slower, older one can land last. Check cancellation after each `await`, and drop results from an older generation. `CarPlayController.swift:67-83`
- On connect, the tabs are built empty and filled by an untracked `Task`, so Listen Now shows "No episodes yet / Add a source on your iPhone" until the first snapshot lands. Pushed pages have no empty-view text at all, so an empty playlist is a blank screen. Set the empty variants only after the first load, and give pushed lists their own. `CarPlayController.swift:33-39`, `:89-94`, `:102-103`
- The car's fallback picture (`CarArtwork.tile`: `LibraryArt` colour and symbol) isn't the phone's or lock screen's (`GeneratedCover` via `LibraryArt.image`). The comment says it follows "the same order the rest of the app uses". So the same episode shows three different placeholders on the phone, lock screen and car. Render `GeneratedCover`'s gradient and motif with `CoverStyle` in UIKit, or accept the difference and fix the comment. `CarArtwork.swift:10-11`, `:50-68`
- The CarPlay code, the CarPlay framework link and the manifest's CarPlay scene ship in every Release build, but `make release` never sets `CARPLAY=1`. Until Apple grants the entitlement, none of it can run. Fence it with a compilation condition, or keep it as is but say so in `project.yml`. Step 14 covers the build side. `Makefile:9`; `scripts/install-ios-device.sh:21-24`; `project.yml:51-59`
- `ArtworkTile` always builds `GeneratedCover` (a `GeometryReader`, `Canvas`, and up to three `Text`s with a `.shadow`, which needs an offscreen pass) under the picture, even when the opaque picture covers it. In long lists, that is per-row cost for nothing once the image has loaded. Keep a greedy `Color.clear` base, and show the cover only while `image == nil`. `ArtworkTile.swift:70-79`, `:82-94`; `GeneratedCover.swift:73-74`
- Dead code: `sectionTitle()` has no caller, and nothing passes `UnfoldingPicker.valueAlignment`, so its `.leading` branches are dead. Delete both. `UnfoldingPicker.Option.id` is the label, so two options with the same text (for example, two models with the same display name) give `ForEach` duplicate IDs. Key on `value`. `SectionTypography.swift:26-28`; `UnfoldingPicker.swift:41`, `:59`, `:79-96`
- `FlowLayout` places a chip wider than the row at its unconstrained width, so a long tag or term runs off the screen edge. Propose `min(size.width, availableWidth)`. It also measures each subview twice per pass with no cache. Measure once into `cache`. `FlowLayout.swift:24-27`, `:45`
- `TagField`'s duplicate check is case-sensitive and trims spaces only, so "AI" and "ai" (or a pasted "AI\n") both get added. `ForEach(names, id: \.self)` also breaks if the stored list ever holds an exact duplicate. Compare case-insensitively after `.whitespacesAndNewlines`. `TagField.swift:34`, `:92-97`
