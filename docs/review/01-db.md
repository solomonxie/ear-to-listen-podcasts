# 01 DB (`Sources/DB`)

Summary: one launch-crash path for old installs, two silent data-loss paths (merge, edit save), and several O(N²) write paths caused by missing or unused indexes. **P0 1 · P1 3 · P2 11 · P3 16**

## P0

**1. Upgrade migrations v31/v32 run current-model code. Any database from before v32 that has episodes crashes on every launch.**
`Migrations.swift:544`, `:581-586`; `DatabaseManager.swift:20-21`
- v31 calls `Track.filter(...).fetchAll`, and v32 calls `Track.fetchAll`. Both decode today's `Track`, which has a non-optional `needsTags: Bool`. That column only arrives in v44. Synthesized `Decodable` ignores the default value, and GRDB throws `columnNotFound` (`Row.swift:1040`).
- v32 also runs `TrackFile(primaryOf:).insert`. GRDB inserts every encoded column, including `transcriptPaths`, which doesn't exist until v33, so the insert throws "no such column".
- `TrackMerge.foldDuplicates` runs inside v32 with foreign keys off. Deleting a duplicate doesn't cascade, so leftover `transcripts`, `trackTerms` and `playlistTracks` rows would also fail the end-of-migration FK check.
- `try!` in `DatabaseManager.init` turns any of these into a crash loop with no recovery.
- Scenario: a TestFlight install from before 2026-09-25 (v32 landed in `8f6109e`; TestFlight config was added in `6d6b2d3` on 09-12) updates to the current build. It crashes at launch every time.
- Fix: freeze old migrations to raw SQL, never models. For example:
  ```sql
  INSERT INTO trackFiles (id, trackID, providerID, filePath, sizeBytes, contentHash, transcriptPath, remoteModifiedAt, isLost, addedAt)
  SELECT lower(hex(randomblob(16))), id, providerID, filePath, sizeBytes, contentHash, transcriptPath, remoteModifiedAt, isLost, CURRENT_TIMESTAMP FROM tracks;
  ```
  Do the v31 backfill with `Row`s. Run the v32 fold in SQL with explicit child deletes, or defer it to a post-migration step that runs with FKs on. Replace `try!` with a caught error: move the file aside and show an error screen.

## P1

**2. `TrackMerge` folds every duplicate onto the original keeper struct, so with 3+ copies the earlier folds are overwritten.**
`TrackMerge.swift:19-24`, `:102-106`, `:130`, `:184`
- `fold(_:into: keeper)` starts from `var kept = keeper` each time and ends with `kept.update(db)`. Folding C writes back the keeper as it was before B was folded in. B's favorite, notes, summary, listenedAt and progress are lost, and B's row is already deleted.
- `foldAll` (`:76-79`) also passes `twins` taken from the initial fetch. A twin that absorbed data as an earlier keeper is folded using a stale struct.
- Scenario: the same episode exists in three buckets, and only the copy that isn't kept was favourited and annotated. After the fold, the favourite and the notes are gone.
- Fix: thread the result through: `var kept = keeper; for d in rest { kept = try fold(d, into: kept, in: db) }`. Re-fetch twins inside `foldAll`.

**3. `saveEdit` → `upsert` saves the whole caller-held `Track` (lost update).**
`TrackStore.swift:252-256`, `:53`; callers `EpisodeEditView.swift:280-292`, `EpisodeDetailsPane.swift:357-364`, `:402-407`
- The edit screens copy `track` when they open and save `updated = track + edits`. When the id matches, `upsert` does `row.save(db)` with every column.
- Anything written in between gets reverted:
  - `positionMs`/`lastPlayedAt` from `PlaybackEngine.persistProgress`
  - `isFavorite`, `listenLater`, `listenedAt`
  - `summary` from the AI pass
  - `providerID`/`filePath`/`isLost` moved by `markLost` or `deleteAll(forProvider:)`. Writing these back also re-links a dead path through `link()`.
- Scenario: the user pauses, edits notes in the details pane, and saves. The resume point jumps back, and a summary generated meanwhile is wiped. That summary was a paid AI call.
- Fix: `saveEdit` should re-fetch inside the write and copy only the edited fields (title, artistID, albumID, year, notes, artworkFileName, durationMs, metadataEditedAt). Or use a targeted `UPDATE`.

**4. PLAUSIBLE: the restore-undo snapshot is a raw file copy of a DB in rollback-journal mode, taken while writes may be in flight.**
`DatabaseManager.swift:49-62`; `LocalBackups.swift:76-87`
- `DatabaseQueue` doesn't enable WAL, and no `journal_mode` is set anywhere, so `checkpoint()` and `purgeWriteAheadLog()` are no-ops.
- `copyItem` runs outside the queue. A sync commit during the copy produces a torn file.
- Scenario: "undo restore" opens a corrupt snapshot.
- Fix: write the snapshot through `dbQueue.backup(to: DatabaseQueue(path: destination))` or `VACUUM INTO ?` inside `dbQueue.writeWithoutTransaction`.

## P2

**5. `trackSearchIndex` (FTS5) is written everywhere but never read, and each write is a full scan.**
`TrackStore.swift:55-59`, `:145-148`, `:221-225`, `:305`; `TrackMerge.swift:180`; `Migrations.swift:64-69`
- `TrackStore.search` has no callers.
- `trackID` is an UNINDEXED FTS column, so `DELETE ... WHERE trackID = ?` scans the whole index on every upsert, tag read, fold and delete. That makes sync, restore and `deleteLost` O(N²).
- Fix: add a v47 migration with `DROP TABLE trackSearchIndex`, and remove the writes and `search()`.

**6. Lost-episode relink scans `tracks` for every listed file.**
`TrackStore.swift:84-88`, `:103-107`, `:136`
- `registerListed` calls `relink` once per new file. It filters on `contentHash = ? AND sizeBytes = ? AND isLost = 1`, and `contentHash` has no index. That is O(files × tracks) inside one write transaction, which blocks the whole queue on a first sync of a large bucket.
- Fix: `CREATE INDEX idx_tracks_lost_hash ON tracks(contentHash, sizeBytes) WHERE isLost = 1`, or load lost rows into a dictionary once.

**7. `foldArrival` does a full table scan on every tag read.**
`TrackMerge.swift:42-45`, called from `TrackStore.swift:227`
- `isLost = 1 AND (filePath = ? OR filePath LIKE '%/x' OR albumID = ?)` uses a leading wildcard inside an OR, so no index applies.
- It runs for every enriched file whose fingerprint has no twin, which is the common case.
- Fix: add a partial index `ON tracks(albumID) WHERE isLost = 1` and run the queries as separate selects. Or keep an in-memory lost-name map per drain.

**8. `DatabaseQueue` serializes all reads and writes, so main-actor DB calls wait behind long background transactions.**
`DatabaseManager.swift:15`, `:20`
- Long transactions include `registerListed` for a whole bucket, `foldAll`, `numberDuplicateTitles` and `TranscriptSearch` scans.
- Main-actor callers include `PlaybackEngine.swift:518` (`@MainActor`, every 5 s) and `HomeLibraryViewModel.swift:181`, `:200`.
- Scenario: UI hitches while a big bucket is scanned.
- Fix: use `DatabasePool` (WAL; reads run alongside writes), which also makes `checkpoint()` real. Chunk huge writes.

**9. Folder stats and the offline directory listing match folders wrongly and miss second copies.**
`TrackStore.swift:565-614`
- `LIKE 'prefix%'` is case-insensitive and treats `_`/`%` as wildcards. `Talks/` pulls in `talks/…`, `a_b/` pulls in `aXb/…`, and `dropFirst(prefix.count)` then produces wrong folder names.
- Both functions query only `tracks` (the playing copy), so second copies in a bucket (`trackFiles`) aren't counted or listed.
- Fix: match with `filePath >= ? AND filePath < ?` (prefix + `\u{FFFF}`, which can use an index) over `trackFiles`.

**10. `TranscriptSearch` matches against the raw JSON text, which misses real hits and ranks wrongly.**
`TranscriptSearch.swift:73-79`
- `JSONEncoder` escapes `/` as `\/` and `"` as `\"`, so queries like "24/7" or "AC/DC" never match.
- SQLite `lower()` only folds ASCII, while the needle is lowercased in Swift, so "Über" never matches "über".
- Needles that are JSON keys or engine values ("text", "start", "end", "file", "whisper", "device") match every row. The 30-row cap then keeps the rows where the key repeats most, not the real hits.
- Fix: keep a plain-text column (lowercased in Swift) or an FTS5 table of line text, and match on that.

**11. `find(filePath:)` does two full scans plus per-id fetches, and restore calls it once per backup entry.**
`TrackStore.swift:478-487`; `BackupService.swift:259`, `:387`
- Neither `tracks.filePath` nor `trackFiles.filePath` is indexed on its own.
- Fix: `CREATE INDEX idx_trackFiles_path ON trackFiles(filePath)`, and do one join query.

**12. `setListened` makes one ChangeLog record per id.**
`TrackStore.swift:432-434`
- Each record is a UserDefaults write, a file append and a main-queue `.backedUpDataDidChange` post. Marking an album of 200 episodes posts 200 notifications, which breaks the repo's coalescing rule.
- Fix: write one entry with the id list.

**13. Renaming a speaker or album to a name that already exists fails silently.**
`LibraryStore.swift:43-60`, `:157-170`; caller `SpeakerDetailView.swift:264`
- The rename hits the unique index (`artists.name COLLATE NOCASE` or `idx_albums_artist_name`). The callers' `try?` swallows the error, so the name, bio and profile typed in that save are all dropped.
- Fix: detect the collision, then offer a merge or show the error.

**14. PLAUSIBLE: `isLostTwin` folds different episodes that share a title.**
`TrackMerge.swift:87-94`
- A candidate with a `nil` duration counts as close enough, and the same album plus the same `DuplicateTitles.base` counts as a match.
- Scenario: a lost "Q&A (2)" with no length is folded into a newly arrived "Q&A", and its bookmarks and notes move to the wrong episode.
- Fix: require both durations to be known for a title-only match.

**15. PLAUSIBLE: transcript read-modify-writes span two transactions.**
`TranscriptStore.swift:36-41`, `:161-171`, `:188-209`; `YouTubeTranscripts.swift:39-51`
- `merge`, `applyEdit`, `split` and `merge(starts:)` read the transcript in one transaction and save it in another.
- `YouTubeTranscripts.adopt` decides "has no transcript" before an `await` download, then calls `save` unconditionally. It can overwrite a transcript made or edited in the meantime.
- Mitigation: the runner is `@MainActor`, so in-app races are mostly serialized.
- Fix: do the read, merge and save inside one `dbQueue.write`. `adopt` should re-check inside that write.

## Improvements (P3)

- `syncJobs` only has an index on `providerID`. `dequeueNextPending`, `hasPending`, `counts` and `unfinished()` filter by status and sort by `createdAt`. Add indexes on `(status, createdAt)` and `(providerID, filePath)`. `SyncJobStore.swift:145-149`, `:202-215`
- `markNeedsTags` and `clearNeedsTags` run one UPDATE per id. The `IN (?,…)` list is unbounded (SQLite allows at most 32766 variables), so chunk it. `TrackStore.swift:172-187`
- `markLost` and `deleteAll(forProvider:)` fetch per touched track. Load them with one `trackID IN` query. `TrackStore.swift:267-289`, `:695-726`
- `numberDuplicateTitles` re-fetches each track it already holds. `TrackStore.swift:659`
- `recordProgress` and `touchLastPlayed` fetch and save the whole row to change one or two columns. Use a targeted `UPDATE`, which also shrinks the lost-update surface. `TrackStore.swift:729-736`, `:811-817`
- `applyTags` repeats the logic of `LibraryStore.upsertArtist` and `upsertAlbum`. `TrackStore.swift:196-210`
- Dead code: `TrackStore.search`, the `tracks.prefersVoice` column (not in `Track`), and the `isDemo` columns.
- `adoptLegacyDatabase` moves `-wal`/`-shm` files, but in rollback-journal mode a hot journal is `-journal`. `DatabaseManager.swift:31`
- Doc comments are on the wrong functions. `reassignAlbumArtist`'s doc and its `@discardableResult` sit on `clearAlbumArtist`, and `updateAlbum`'s doc sits on `updateAlbumLanguage`. `LibraryStore.swift:107-116`, `:145-148`
- Swallowed errors: `FixHistoryStore.record` uses `try?` (`:18`), and `TranscriptStore.find(trackIDs:)` silently drops rows it can't decode (`:121`).
- One unknown `AiVendor` raw value (from a newer backup or a downgrade) makes `AiKeyStore.all()` throw for every key. Decode leniently and skip that row. `Models/AiKey.swift:144`
- `AiKeyStore.add` writes the Keychain before the DB insert, so a failed insert leaves an orphaned secret. `remove` deletes with `try?`. `AiKeyStore.swift:28-29`, `:44`
- `BookmarkStore.add` checks and inserts in two separate transactions, so a double tap can create a duplicate. `BookmarkStore.swift:13-18`
- Removing a source runs `deleteAll(forProvider:)` and `providerStore.delete` as two transactions. `trackFiles.providerID` has no FK, so files that an in-flight drain inserts between them are orphaned. `SettingsViewModel.swift:189-190`, `Migrations.swift:565`
- `setTerms`: input names that differ only in case ("AI" and "ai") map to one term, and the last count wins instead of the counts being summed. `TermStore.swift:21-32`
- `fold` moves `transcriptEdits` even when the keeper keeps its own transcript, so the edits point at segment starts that no longer exist. `TrackMerge.swift:168-178`
